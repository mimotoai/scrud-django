# UI Split (ninja phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the htmx UI from its own Django app, mounted at `/` (and under
each published branch's prefix), reading and writing through the
framework-neutral core, and make `/api/...` JSON only.

**Architecture:** The UI types' viewset behaviour becomes core hooks on
`core.types.TypeOptions`, so the core alone can read and write them. The
renderer's body is extracted into a plain function, `render_html`, that
plain Django views in `scrud_django/ui/pages.py` call after core reads and
writes. `scrud_django/ui/urls.py` (namespace `scrud_ui`) routes registered
slugs, the CSS/JS files and the studio. The studio's endpoints and the
embeds stop dispatching DRF viewsets in process. The prefix middleware then
maps to the UI views, and finally the API stops negotiating HTML. Until that
last step, HTML on `/api/` stays as a shim so the suite is green after every
task.

**Tech Stack:** Django 5, django-rest-framework (the DRF adapter only),
htmx, Jinja templates (`scrud_django/ui/engines.py`), scrudful, scoped-rbac,
safetydance/safetydance-django tests, node for the JS harness tests.

**Spec:** `docs/superpowers/specs/2026-11-11-ninja-front-end-design.md`, §2
(lines 289-366), "Testing" (Phase 2) and "Breaking changes". Fact-finding
report (read-only reference, line numbers as of `feature/ninja-own-models`
01b95f7): `/private/tmp/claude-501/-Users-davidcharboneau-dev/2b56465c-b343-4839-a25f-ccc5e8fdae69/scratchpad/phase2-facts.md`.

## Owner decisions and rulings this plan carries

- **(owner, 2026-11-16) UI writes go to UI URLs.** The UI views at `/` (and
  under prefixes) also accept the writes the API route serves (`POST` on a
  list, `PUT` and `DELETE` on an item), write through the same core
  functions as the API, and answer with HTML exactly as today: the
  re-rendered frame, the refused-PUT edit form with field errors, the
  412/409 reloading notice. This replaces spec §2.2's "htmx writes keep
  going to the JSON API". A frame's write href and navigation href stay the
  same value (the UI URL). Task 11 records the decision in the spec.
- **Ruling: `/api/` never answers *scrud UI* HTML.** DRF's default renderers
  include `BrowsableAPIRenderer`, so a browser's `Accept` still gets DRF's
  browsable API (`text/html`) from `/api/` (spec §2.1's "JSON" is wrong on
  that point; Task 11 corrects it). The tests assert no `scrud-resource`
  markup and no `ScrudHTMLRenderer`, not "no `text/html`". ninja drops
  `SCRUD_HTML` from its offers (`scrud_django/ninja/negotiation.py`).
- **Ruling: route names are `scrud_ui:list` (kwarg `slug`) and
  `scrud_ui:detail` (kwargs `slug`, `pk`)**, not per-slug names (spec §2.2's
  `scrud_ui:<slug>-list` is a (call)): types registered after the URLconf
  loads (`register_or_defer`) cannot get per-slug patterns. A path converter
  claims a slug only if it is served (see Task 5), so app URLs are not
  swallowed.
- **Ruling: the studio is included by `scrud_django.ui.urls`** at `studio/`
  (namespace `scrud-studio`, unchanged) when `scrud_django.ui.studio` is
  installed. Projects drop their own `include("scrud_django.ui.studio.urls")`.

## Review Focus

1. **A UI write without the CSRF token** (session user, `enforce_csrf_checks=True`)
   is refused 403 and writes nothing, for the item PUT/DELETE, the list POST
   and every studio POST endpoint. Pinned in Task 5.
2. **A user who may not read a resource, or not write it,** gets the same
   status from the page as from `/api/` (403 or 404, hidden == missing), for
   GET, PUT and DELETE, including an anonymous user. Pinned in Task 5.
3. **An app URL that looks like a UI route** (`/shop/todo-lists/` in
   `tests/mounted_urls.py`, an unregistered slug, a slug without its
   trailing slash under a prefix) is not swallowed or redirected by the UI.
   Pinned in Tasks 5 and 9.
4. **A stale `If-Match` on a UI PUT or DELETE** answers 412 with the
   reloading frame and writes nothing; a missing one answers what the API
   answers (428 where the API requires it). Pinned in Task 5.
5. **A stored component template that still names an `/api/...` path**
   through `embed(...)` or `in_mount(...)` keeps rendering the UI's HTML
   (the path is mapped to the UI), while a raw `hx-get="/api/..."` gets
   JSON (documented as a breaking change). Pinned in Tasks 6 and 10.
