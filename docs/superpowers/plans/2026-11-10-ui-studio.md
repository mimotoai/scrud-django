# UI Studio (bootstrap) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bootstrap studio app, `scrud_django.ui.studio`, for authors. Its loop is: find a type, preview a schema sample of it, click a node to inspect, edit or create a Jinja component and its rule on a working branch, and save so the preview re-renders.

**Architecture:**
- **Pages:** package-template Django pages with htmx. The preview loads in an `<iframe sandbox="allow-same-origin">`, so branch scripts never run there; the studio page's own script handles clicks inside it.
- **API:** every capability is a JSON or fragment endpoint, the studio's API (sample, preview, explain, new-component), so a later self-hosted studio can reuse it.
- **Writes:** they reach the existing resource views by in-process dispatch, with the same user and every check. The studio has no authorization code of its own.

**Tech Stack:** Django 5.2, DRF, scoped-rbac, Jinja2, htmx 2.0.4 (vendored), safetydance 0.5 tests.

**Spec:** `docs/superpowers/specs/2026-11-10-ui-studio-design.md`. Read it first. Background:
- `docs/ui.md`, including its Branches chapter;
- `docs/superpowers/specs/2026-11-09-ui-branches-design.md`.

## Global Constraints

- **Branch and app.** Work on `feature/ui-studio` in `/Users/davidcharboneau/dev/scrud-django-ui-branches`. Don't bump the version (CLAUDE.md: work merges into `develop`).
- **App.**
  - `scrud_django.ui.studio`, label `scrud_django_ui_studio`. It requires `scrud_django.ui` (a system check error if it's missing).
  - A project includes `scrud_django.ui.studio.urls` at a path it chooses. Tests use `studio/`.
  - Every studio view requires an authenticated user (401/redirect as DRF/Django do).
- **No stored components in studio pages (spec anti-goal).** Studio templates live in `scrud_django/ui/studio/templates/scrud_studio/`. Static files live in `scrud_django/ui/studio/static/scrud_studio/`. No inline `<script>` and no inline event handlers, because CSP is `script-src 'self'`.
- **Writes.**
  - Writes go only through `studio/dispatch.py` `call_view` into the resource viewsets, so all existing checks apply (RBAC, R36, R14 base, versions).
  - A studio write naming a published branch (one with a `prefix`) is refused with 400, problem type `ui-studio-branch-read-only`, before any dispatch.
- **Reads.** The studio shows only what the per-row read checks allow (R9-style). In the inspector, a rule from a stylesheet the user can't GET shows only `{"readable": false, "rank": [...], "outcome": ...}`.
- **Selections.** The studio validates an explicit branch selection with `selection.selectable(request, selection)` (Task 3). That means GET on the branch and its working ancestors, an intact chain, and present snapshots. There is no prefix-tree check.
- **New component (spec Goal 5).**
  - The match options run from most to least specific (`node.terms` order).
  - The default is the first.
  - A schema-type term is labelled `"every <type>[ format=…| enum] on this branch"`.
  - Rules are written to the stylesheet named `studio` on the branch, for the chosen `applies_to`, created on first use.
  - "Inside this type" adds the scope `"<property>-in-<parent component name>"` to the parent component's `scopes` (an override on the branch if inherited), and uses that scope in the selector.

## Review Focus

1. **A schema with `$ref` cycles, `oneOf` with no usable branch, `type` as a list, or `additionalProperties` only.** The sample must still be built, with depth capped and no exception. Test in Task 2.
2. **A node whose pointer contains `~` or `/` in a property name.** The click → explain → new-component path must escape and unescape it correctly. Test in Task 4.
3. **Two saves of the same component in two tabs.** The second must get the 412 notice and reload the editor, never overwrite silently. Test in Task 5.
4. **"New component" when a component of the generated name already exists on the branch.** The name gets a numeric suffix, never a 400. Test in Task 6.
5. **An inspected rule whose component is inherited from a branch the user can read, but whose stylesheet they can't.** The winner shows as unreadable, and the component name is not revealed. Test in Task 4.

### Task 5: In-process dispatch and studio writes

**Files:**
- Create: `scrud_django/ui/studio/dispatch.py`, `scrud_django/ui/studio/writes.py`

**Interfaces:**
- Produces:
  - `call_view(request, slug: str, method: str, *, pk=None, data=None, if_match=None, headers=None) -> Response`. It builds an internal request for `reverse(f"{slug}-list"|"-detail")`:
    - built with `django.test.client.RequestFactory`, with the JSON body;
    - `_force_auth_user = request.user`;
    - `_dont_enforce_csrf_checks = True`, safe because the studio request itself passed CSRF;
    - `HTTP_ACCEPT="application/json"`.

    It resolves the view and calls it, then renders and returns the DRF `Response`.
  - Write endpoints. They are POST with a JSON body and answer JSON, plus `HX-Trigger: scrud-studio-saved` on success. Names `scrud-studio:<verb>`:
    - `save-item`: `{kind, branch, name, applies_to?, content}`. It creates the override on the branch if the item is inherited (POST), else PUTs with the client's `If-Match`.
    - `revert-item`: `{kind, branch, name, applies_to?}`. It DELETEs the branch's own row.
    - `pull`: `{branch}`. It PUTs the branch with `pull: true`.
    - `push`: `{branch, target?}`. `target` defaults to the parent. It POSTs a `ui-pushes` resource in `applied` state.
  - Every write endpoint:
    - refuses a published branch (`UIStudioBranchReadOnlyError`);
    - passes the resource view's error status and problem body through unchanged (400, 403, 409, 412).
  - `writes.own_item(kind, branch, name, applies_to) -> Resource | None` reads unsorted (`scrud_django.rows`).

    ```
    {"matches": [{"select": str, "label": str, "broad": bool}],

     "where": [str],
     "applies_to": [str],
    ```
